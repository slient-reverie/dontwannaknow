## 一、他的方法论（三条支柱）与我们怎么落地

| 他的原则 | 原话要点 | 我们怎么落地 |
|---|---|---|
| **① 在"做"中理解** | 先触摸再理解；每个概念都要能上手；感受比讲解重要 | 每节课必须动手跑一遍，不许只看不练 |
| **② 克制而完整** | 有勇气说"现在不讲"；步骤级目标；关注"是什么"而非"怎么做" | 不钻语法细节，先建立"它在解决什么问题"的直觉 |
| **③ 不写代码，管理它** | 代码由 AI 生成，学习者负责理解原理、使用和运行它 | 你少手写，但必须通过"理解三问 + 改动测试" |

> ⚠️ 关于第 ③ 条：**"少手写"不等于"当黑箱"**。看不懂的东西，上线后出问题只能干瞪眼。所以这里加了"理解三问 + 改动测试"作为底线。

## 三、五份大作业（全部围绕"热量与财务管理"产品）

> 原则：**每一份都是你产品的真实一步**，不是练习题。

### 作业 1《让世界看见你的网页》— 对应 2.2 / 2.3 / 2.4 / 3.3 / 3.4 / 3.5
- **目标**：把已经做好的 v0/v1 页面，真正发布到一台公网服务器上
- **交付物**：
  1. 终端闭环练熟（建目录→进目录→建文件→Vim 编辑→查看→删除）
  2. 代码推到 GitHub 私有仓库
  3. **用 GitHub Pages（免费）把页面发布到公网**；云服务器 + Nginx 方案**延后到作业 5**（省钱决定 2026-10-27）
     - ⚠️ 免费版 Pages **不支持私有仓库** → 为网站**新建一个公开仓库**（如 `zero-to-tech`），只放网页代码
     - ⚠️ **千万别把现在的私有仓库改成公开**（里面有记账数据等个人信息）
- **验收（3 项，共 100 分）**
  - 功能 40%：手机 4G 打开你的 **GitHub Pages 网址**，能看到页面
  - 理解三问 30%：①`pwd`/`ls`/`cd` 各解决什么问题？②Nginx 在这条链路里干什么？③`git push` 和"部署"是什么关系？
  - 改动测试 30%：我让你改页面标题 → 你独立完成"改→提交→部署→刷新看到"
- **预计**：3~5 天（每天 1~2 小时）

### 作业 2《React 版热量计算器》— 对应 4.1-4.6
- **目标**：把计算器从"手写 DOM"升级成 React + Next.js 项目
- **交付物**：组件化界面（输入食物/克数/结果展示），数据驱动渲染
- **验收**
  - 功能 40%：输入 → 点按钮 → 显示热量；手机端正常
  - 理解三问 30%：①为什么要把页面拆成组件？②`import/export` 解决什么问题？③Next.js 比 React 多了什么？
  - 改动测试 30%：加一个"清空"按钮 / 把结果改成"每 100 克 + 总热量"双显示
- **预计**：1~2 周

### 作业 3《食物热量查询接口》— 对应 5.1-5.5
- **目标**：用 FastAPI 写一个真接口，前端从接口拿数据（不再硬编码）
- **交付物**：`GET /api/foods/{name}` 返回 JSON（食物名、每 100 克千卡）；前端 fetch 调用并展示
- **验收**
  - 功能 40%：浏览器直接访问接口能看到 JSON；页面从接口拿到数据
  - 理解三问 30%：①接口和普通网页的区别？②状态码 200/404 分别什么意思？③CORS 为什么需要？
  - 改动测试 30%：加一个食物 / 加一个"全部食物列表"接口
- **预计**：1 周

### 作业 4《把记录存进数据库》— 对应 6.1-6.6
- **目标**：饮食与消费记录存进 SQLite，加用户会话（每人只看自己的）
- **交付物**：表结构 + 增删改查接口 + 登录会话（cookie/session）+ 重启服务数据还在
- **验收**
  - 功能 40%：记录后重启服务数据还在；换浏览器登录看不到别人的数据
  - 理解三问 30%：①为什么文件存储撑不住？②`session_id` 是怎么让服务器认出你的？③SQL 注入是什么、怎么防？
  - 改动测试 30%：加"删除某条记录" / 加"按月汇总"
- **预计**：1~2 周

### 作业 5《正式上线》— 对应 7.1-7.3
- **目标**：域名 + HTTPS + 服务常驻，正式可用
- **交付物**：`https://你的域名` 手机电脑都能用；systemd 常驻；证书自动续期
- **验收**
  - 功能 40%：手机 4G 打开 https 站点，注册 → 记录一条 → 刷新数据在
  - 理解三问 30%：①systemd 解决了什么？②反向代理在转发什么？③证书为什么能防"中间人"？
  - 改动测试 30%：改一处配置并重启发布（如换端口/加一条 location）
- **预计**：1 周（域名备案要预留 1~3 周）

## 四、防"复制粘贴"的机制（核心规矩）

### 规矩 1：理解三问（每个作业必答）
1. 这个文件/这个函数**为什么存在**？（它在解决什么问题）
2. 如果**改掉某个数值/参数**，会发生什么？
3. 出错时，**你从哪条信息**定位问题？（报错行？状态码？日志？）

### 规矩 2：改动测试（我来出题）
作业验收时，我临时要求改一处功能，你**独立完成**。不许说"你直接给我代码"。
可以查文档、可以搜报错，但**不许把整个需求丢给 AI 生成**。

### 规矩 3：允许 AI 写，但必须是"你的项目"
- 可以：让 AI 生成一个组件、一个接口、一段 SQL
- 必须：你自己写需求、改参数、调试、验收
- 禁止：把别人（或 demo）的整份项目复制过来当自己的作业

### 规矩 4：卡住 30 分钟规则
自己看报错、看文档、搜关键词，**卡满 30 分钟**再来问我。
（这条是为了练"不求人"的能力，不是故意为难你。）

## 六、节奏与流程

**建议节奏**：每周 4~5 次，每次 1~2 小时；每 5~7 天完成一个小交付。

**每次学习的固定流程（照做就行）**

5. 完成当天一个小交付（改一个功能 / 修一个错）
6. 写 3 行日志：学了什么 / 卡在哪 / 明天做什么
